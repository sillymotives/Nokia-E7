# E7 Bridge: early post-boot and settled-state baselines

Prepared: 2026-10-10. Status: host-only analysis workflow; physical three-stage baseline **pending**.

## What this test can and cannot prove

E7 Bridge is **manually started after the Symbian user interface and Wi-Fi are available**. The earliest reachable capture is an **early post-boot snapshot**, not an instrumented cold-boot trace. Process enumeration occurs in non-atomic pages, and memory changes can reflect page cache, background allocation, user interaction or timing. A consistently running process is **not** evidence that disabling it would be safe, nor do zero process changes imply zero CPU work.

This protocol uses the already installed E7 Bridge v0.4.0. It requires **no new SIS, new capabilities, flashing, firmware editing or privileged commands**. Keep Nokia Offline mode as configured. Do not repeat the previously failed no-SIM General-mode forcing experiment.

## Physical baseline protocol

1. On Debian, run the installed v0.4 controller from `bridge/e7-bridge` (or the unpacked v0.4 source), binding to **your current** trusted LAN IPv4 address. Start the session manually on the phone with the existing pairing key. Do **not** publish or rotate the key in GitHub.
2. Restart the E7 normally. After its home screen and Wi-Fi are usable, launch E7 Bridge promptly, connect, and type `capture`. Record the displayed private filename as **A / early post-boot** and note approximate elapsed time since the reboot.
3. Leave the app connected. After approximately three minutes of idle time, type `capture` again, record that filename as **B / settled**, then type `diff`. `diff` compares the two newest `ps save` / `capture` JSON files in the private snapshots folder. Avoid creating unrelated captures between A and B.
4. For optional **C / normal use**, exercise safe existing native features (e.g. music and Files), return to or reconnect the bridge, and type `capture` once more. If the application connection dropped while switching tasks, reconnect before capturing. Don't change settings or services merely for this test.
5. Finally `exit`. Verify Wi-Fi, music and standby, as with the v0.4 acceptance gate.

The `capture` files are automatically saved on Debian under `~/.local/share/e7-bridge/snapshots/`, with owner-only file permissions. Record their **full paths**. Do not include any raw captures, pairing keys, local IPs or personal filenames in the public repo.

## Compare explicitly chosen files

In a second Debian terminal, from the Nokia-E7 repository checkout:

```sh
python3 bridge/e7-bridge/tools/stage_compare.py \
  /path/to/early-e7-diagnostic.json \
  /path/to/settled-e7-diagnostic.json
```

To compare an optional C stage, substitute its path for the later argument. To compare the first and last samples of an existing recorder file:

```sh
python3 bridge/e7-bridge/tools/stage_compare.py \
  /path/to/e7-recording-YYYYMMDDTHHMMSSZ.jsonl
```

The tool accepts the actual filenames generated by `capture`, `ps save` and `record`; the placeholder paths above are illustrative. It reads data offline and never contacts the Nokia. `--json` emits structured comparison results if a private analysis workflow needs them. RAM deltas are shown only when both snapshots have those measurements; raw battery values are not interpreted as percentages. Instance-name comparison uses counters rather than simple sets.

## Interpretation and decision gate

Classify changes as **observed present/absent at different post-boot stages**, **possible on-demand startup**, or **potential snapshot artefact**, never as proven unwanted services. Repeated tests at comparable stages, decoded startup resources, known package ownership and regression/rollback plans must agree before any service can be considered for a reversible change.

Modernisation priorities are in `docs/MODERNISATION-ROADMAP.md`. This baseline is a small piece of that work, not a project to strip Symbian blindly.
